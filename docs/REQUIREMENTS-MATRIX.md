# Capability evidence matrix

This is a generic inventory of the local synthetic preview, not production acceptance. A row can have functioning local code while still lacking required organizational policy or environment validation. Evidence links identify implementation and test cases; test-file existence alone is not a claim that a new run passed. See [VALIDATION.md](VALIDATION.md) for executed results.

Statuses: **implemented-local** = working bounded local capability with regression coverage; **demonstrative** = synthetic adapter or incomplete safeguard requiring more implementation/validation; **intentionally-disabled** = unavailable by design pending authorization and engineering; **missing** = no complete implemented capability or accepted external decision. These labels are not a completion percentage.

## Next useful local work

1. Add a synthetic, idempotent workspace-provisioning seam with stable identifiers, failed-validation isolation and duplicate-request tests. Keep real membership and study approval external.
2. Extend migration rehearsal with explicit source/target write ownership, source-link resolution and rollback that preserves target edits. Batch receipts do not establish full source inventory or wave acceptance.
3. Extend search with agreed owner/date filters and remaining metadata coverage; test saved links to moved, renamed and migrated records. Add structured milestones/blockers only where the study journeys justify them.
4. Agree catalog review and resource attestation policy before extending local lead-managed templates into an organizational catalog. Preserve existing definitions and captures when policy changes.
5. Agree records/hold semantics before adding disposal, then test all mutation, import and cleanup paths. Approved scanning, quota and orphan accounting remain separate work.

Production identity, real SQL concurrency/recovery, Windows/IIS behavior, accessibility acceptance, approved service targets and operational ownership require their own evidence. They cannot be closed by more synthetic screens or by interpreting local tests as production validation.
