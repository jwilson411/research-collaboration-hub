## Session-context correction

Independent review reproduced a synthetic multi-tab attribution defect in the prior candidate: a discussion drafted as one identity could save as the identity selected in another tab, and a stale tab retained its previous workspace. The earlier passing suites did not cover this sequence. That candidate was held for correction; its results above remain historical evidence, not closure of this finding.

The correction uses a server-held actor and rotating session generation, serialized with all requests for that session. Every mutation requires the intended generation in addition to CSRF. Old-generation writes, including replay, are rejected before endpoint execution. An admitted write may complete under its original actor before a queued switch is acknowledged. The focused HTTP suite passed eight tests in 33.455 seconds, including a deliberately delayed request body, aborted-body recovery, simultaneous switches, return to the original actor, restart invalidation, legacy-cookie spoof rejection, authorization-context changes and bounded session capacity.

Independent Chromium checks passed the corrected two-tab sequence, duplicate channel/storage notifications during a delayed refresh, back/forward and focus revalidation, task and administrator drafts, original-identity draft/file exports, mapping revocation and restored access, delayed file reads after an identity change or study navigation, an intercepted pending mutation and a fresh correctly attributed save. The exercised recovery view had zero axe violations; no page errors or external requests were observed. Browser review found and corrected an overlapping focus/refresh race that left verified content hidden; a separate test-interception cleanup issue was fixed in the harness before the successful fresh-state run.

Draft recovery is memory-only and requires current access. An interrupted write can already have committed under its original actor; it is never automatically resubmitted. Closing or reloading the tab loses retained drafts. See [session context and limits](SESSION-CONTEXT.md).
